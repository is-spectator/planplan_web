状态（2026-11-16）：恢复核对、账户隔离、计划内对话、15秒版本/日期核对、消息独立刷新、冲突对照与反馈提交/回复/追踪已在本机实现并完成相应回归，见[实施进度](implementation.md)。P03/P12/P14的交叉证据见[全版本TODO（12/18）](todos/2026-11-16-platform-completion.md)、[132项浏览器报告](template-platform/platform-frontend-qa-2026-11-16.md)和[重启/恢复验证](template-platform/platform-final-verification-2026-11-16.md)。真实iOS/Web跨端、真实设备、目标环境维护与发布、独立试用仍未完成，整阶段不勾选。建议累计邀请10–20人，尚非实际人数；这是基础MVP验收范围。

本版继承[v0.2](v0.2-daily-use.md)的适用能力与共用门槛。当前下一开发目标为[v0.4模板平台](v0.4-template-platform.md)，本文件的未完成基础验收继续保留。

## 用户价值

用户在手机和电脑之间切换仍能继续使用；遇到网络异常时知道哪些记录已保存、哪些需要核对。使用中的问题可以明确反馈，试用不依赖开发者随时陪同。

## 范围

| 能力 | 相对前版的增量 |
| --- | --- |
| 跨端刷新 | 返回页面、恢复联网、前台期间检查数据版本；iOS/Web 同账户变更可见 |
| 待核对事项 | 在前版原ID核对机制基础上提供统一入口，展示处理中、待核对、需处理及已恢复结果 |
| 并发体验 | 多标签页状态通知、单队列消费、版本冲突前后内容核对 |
| 计划内对话 | 从详情进入并带可清除的计划范围，回答后返回相关详情 |
| 浏览器体验 | 键盘操作、焦点管理、长列表、窄屏输入法与深层路由完善 |
| 反馈闭环 | 应用内反馈入口；在反馈流程中按需查看版本和匿名诊断摘要，不在日常页面常驻开发信息 |

前版已必须正确处理超时、冲突和账户隔离；本版将这些机制集中呈现并扩大真实场景验证，不能以本版为由延后基础正确性。

## 实施工作包

- [ ] 成功写入立即刷新；窗口重新获得焦点和恢复联网时核对版本；前台可见期间每 15 秒检查一次，后台停止轮询并对失败退避。
- [ ] 根据 `dataVersion` 更新业务数据；消息历史独立刷新，不受业务版本是否变化限制。每次刷新同时检查 `/v1/me.today`，上海日期或周期变化时重载当前周期，避免纯查询、澄清和跨午夜场景漏更新。本地测试环境目标为远端成功操作后 20 秒内可见，网络异常时明确显示旧数据状态。
- [ ] 跨端校验使用同一后端与同一邮箱账户；真实 iOS 设备/模拟器可用后执行。资料昵称头像同步和旧账户迁移不包含在本版。
- [ ] 待核对事项中心支持查看原操作、继续核对和允许时的同体重试；不把“本机移除”称为“服务器撤销”。
- [ ] 多标签页协调未完成队列，避免两个页面消费同一项；退出后的旧响应不得重新写回界面。
- [ ] 计划范围标签、键盘发送/换行约定、对话定位和表单焦点完善。
- [ ] 反馈入口连接团队实际维护的渠道；发送前展示内容，不自动附带输入原文、金额、邮箱或令牌。
- [ ] 核验真实目标环境的发布、持久化、备份恢复与受控回滚，完成最终浏览器矩阵。

不新增 WebSocket/SSE；本版刷新是版本检查，不承诺实时多人协作。继续沿用“退出所有设备”，每设备会话放后续。

## 验收演示

1. 同一邮箱账户在 Web 与 iOS 登录。任一端记一笔，另一端返回前台后刷新得到同一数据。
2. 两个标签页打开同一记录；一页修改后，另一页用旧版本保存被拒绝，显示最新内容并重新确认。
3. 发送记录后丢失响应，再刷新页面；待核对入口找回原结果，只有一笔记录。
4. 核对未完成时断网，状态保持未知；恢复后继续查询，不显示虚假成功。
5. 标签页 A 保留未完成操作，另一页切换到账户 B；旧队列因账户不符不能发送或被服务端拒绝，B 的数据不增加。另测 A 请求未返回时切换 B，A 的响应、恢复项和历史不能出现在 B。
6. 使用手机键盘、窄屏、放大文字完成登录、记账、查询和编辑；主要按钮和状态可见可操作。
7. 点击退出所有设备，确认另一个 Web 标签页和 iOS 的旧凭证均失效。
8. 从反馈入口报告问题，只包含用户确认的描述与匿名诊断信息，能够由维护者接收和追踪。

## MVP 放行标准

先通过共用发布门槛和本版技术回归，再向 10–20 人开放候选体验；以下全部完成后才宣告 MVP 完成。

- [ ] [验收清单](acceptance-and-release.md) 所有必测项通过；真实浏览器/设备记录齐全。
- [ ] 至少 5 位非开发参与者完成 7 天试用；其中至少 4 位无需开发者代操作即可完成注册、记录、查询、纠错和重新登录恢复。
- [ ] 试用期间没有未解决的错账、重复落账、跨账户数据暴露、已确认数据丢失或核心登录阻断。
- [ ] 普通问题已分类、明确责任人和后续版本；给用户展示影响使用的已知限制。
- [ ] 真实邮件、模型、备份恢复、发布和回滚有当前候选版本对应证据。
- [ ] 发布记录的前端、后端、数据库迁移与实际环境一致。

上述人数、天数与完成率是提议的验收目标，不是已有结果。尚未满足时继续保留候选状态，先修复问题，再扩大邀请。
