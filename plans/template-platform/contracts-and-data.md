# v0.4 模板平台：契约与数据边界

状态：版本总体约束；阅读第一批契约已落入代码，具体接口与兼容清单见[第一批实现契约](reading-contract-v1.md)，实际验证见[今日 TODO](../todos/2026-11-16.md)。本文覆盖的完整平台实体与能力并非全部已实现。

阶段统一为：**S1 官方模板闭环**，以记账、阅读、饮水验证完整链路及 generic 引擎；**S2 私人对话创作**；**S3 社区发布**。沿用 [共同约定](../00-foundation.md) 的账户隔离、业务日期、幂等、恢复、版本冲突和发布底线。

## 1. 现有事实与改造范围

当前后端只有 `ledger`、`study` 两类计划，以及 `expense`、`refund`、`study` 三类记录；目标参数、操作类型、AI 动作、查询和视图组件也围绕这两类业务固定。`view_config` 仅承载既有组件的隐藏、排序，不是通用模板定义。数据库约束每账户只有一个账本，归档账本也占据此唯一性；现有 `add_expense` 不接收计划 ID。

模板版本、市场作品、创作草稿、独立试用环境与 generic 引擎均属于新增工作。不能仅增加前端卡片或把任意 JSON 放入 `view_config`，就视为模板平台完成。

源码核对入口位于 `is-spectator/planplan`：`server/src/db/schema.ts`、`server/src/services/repo.ts`、`server/src/services/engine.ts`、`server/src/services/views.ts`、`server/src/api/schemas.ts`、`server/src/ai/turn.ts`。以上现状以实施前再次核对的后端提交为准。

## 2. 实体职责

以下为拟定领域实体，不限定必须一一对应数据库表。

| 实体 | 承担的职责 | 必须保持的边界 |
| --- | --- | --- |
| 模板 | 标识可复用的作品及作者，关联创作草稿和版本 | 不存某位选用者的答案、计划进度或实际记录；模板身份与市场曝光状态分离 |
| 模板草稿 | 保存尚在编辑的定义、创作对话和预览状态 | 默认仅作者可见；对话修改先形成可核对的定义变化，不直接改动已选用计划 |
| 不可变模板版本 | 固定引擎、字段、初始化问题、默认配置、视图和指标定义 | 每次供正式选用的定义均有明确版本；发布后不原地覆盖；必须标明所需能力及定义格式版本 |
| 私人计划 | 承载用户日常使用，绑定模板版本与当时的定义、配置快照 | 归选用者所有；不与作者共享数据；模板编辑、下架或作者离开不能改写或删除该计划 |
| 计划配置 | 保存名称、目标、显示偏好及初始化答案等个性化设置 | 与实际完成记录分离；可变目标有生效范围，不能无提示重算历史目标；不回流到公共定义 |
| 事实记录 | 保存用户实际发生的支出、学习或 generic 事件 | 归属账户及计划；有稳定记录 ID、业务日期、字段值和版本；修改、删除、撤销遵守业务引擎规则 |
| 试用会话 | 让用户以合成示例或主动输入试验模板 | 与正式计划、全局统计和聊天上下文隔离；有退出及清理规则；试用输入不自动成为正式事实 |
| 市场作品 | 承载标题、介绍、作者展示、分类、上架状态及可选用版本 | 引用已检查的不可变版本；上架不改变数据所有权；“官方”和“用户创作”身份由服务端管理 |

模板定义说明“可以记录什么、怎样展示”；配置说明“我希望怎样使用”；记录说明“实际发生了什么”。例如“每天喝 2,000 毫升”属于目标，“今天喝了 300 毫升”才是事实。默认示例、预览数据、初始化目标都不能计入完成量。

## 3. 受控定义与引擎边界

模板生成结果是受验证的声明式定义，不是可执行应用代码。AI 只能提出定义或业务操作；服务端按已实现的能力清单验证后执行。模板不能增加新的数据库权限或绕过既有业务规则。

| 引擎 | S1 证明模板 | 负责的业务含义 | 允许模板改变的范围 |
| --- | --- | --- | --- |
| `ledger` | 记账 | 人民币金额、支出与退款关联、预算和账本周期 | 标题、初始化问题、允许的显示选项与目标默认值；金额及退款语义不由模板改写 |
| `study` | 阅读 | 学习时长、按周目标、有效学习日等既有语义 | 阅读名称、目标默认值及已支持的组件组合；不能将任意数量伪装成学习分钟 |
| 新增 `generic` | 饮水 | 受控字段的事件记录及受控聚合 | S1 至少支持日期、整数毫升数量、可选备注、每日目标、按日合计和记录列表；须真实持久化、查询、纠错、删除及恢复 |

generic 是独立新增业务能力，不复用 `study` 记录类型假装支持饮水。实施须一起覆盖服务端校验与执行、存储、AI 动作及查询、结构化回执、前端表单与视图、导出、账户删除、幂等恢复和适用的撤销规则。

受控定义拟包含以下职责；准确字段和上限在 S1 契约冻结时确定：

- **字段定义**：稳定标识、名称、已支持的数据类型、是否必填、有效范围、默认值及可选单位。S1 只开放证明模板必需的类型，扩展枚举、布尔值等类型必须有完整输入、校验、展示和导出支持。
- **初始化定义**：有明确用途的提问、答案对应的配置项、可跳过项和完成条件。提问文案不能自定义写入权限。
- **视图定义**：从组件白名单选择概览、目标、记录列表等组件及排列；不允许 HTML、脚本或任意网络请求。必需的记录与纠错入口不能被模板隐藏到不可达。
- **指标定义**：只能组合已实现的聚合操作和字段，且受数量及查询范围限制；不接受任意公式、SQL、代码或跨计划数据引用。
- **能力声明**：列出模板需要的引擎及能力版本。缺少能力时禁止正式选用或执行相应操作，不在写入后才发现无法展示。

S2的结构化自定义阅读通过generic创建新的私人模板与计划，书名、时长、阅读位置等分别存储。已有study计划继续沿用原引擎的设置和展示能力；跨引擎迁移不在本版，不能将新增字段建议自动变成study到generic的升级。

S2 对话创作只能使用当时已经开放的能力。超出能力的请求应解释限制并允许调整草稿，不能悄悄生成无效控件或声称功能可用。

## 4. 稳定字段、单位与统计口径

- 字段 ID 与用户可修改的中文名称分离。同一语义跨版本保持 ID；改名、排序不产生新字段。已删除的 ID 不分配给另一种语义，旧记录仍能按原定义解释。
- 记录保留解释其数据所需的定义版本。模板更新不能把旧字段值按新的类型、单位或含义读取，也不能把缺失值当成零或默认已完成。
- 金额继续使用整数分，学习时长继续使用既有分钟语义，饮水使用整数毫升。模板显示单位必须明确；输入换算只开放服务端支持的精确规则，不允许通过显示文案改变存储含义。
- 每个指标固定来源字段、聚合方法、业务日期、时区、周期、缺失值和删除记录处理。记录条数、有效天数、数量合计是不同指标，不能互换。平均值或达成率必须说明分母；未定义分母时不生成此类指标。
- 业务日期沿用 Asia/Shanghai；统计按事实的业务日期，不能按聊天发送时间或记录更新时间替代。饮水按日合计，阅读保留 study 既有周目标口径，账本保留现有预算及退款口径。
- 同一指标在聊天回答、计划详情、列表摘要和导出中的口径一致，由后端给出权威结果。AI 不自行重算并覆盖服务端结果。
- 改变目标要明确生效日期或周期；历史完成量不变。改变聚合口径属于语义变更，不能以“调整展示”名义自动更新旧计划。

## 5. 选用、初始化与唯一账本

选用契约至少要表达：当前账户、确定的模板版本、初始化配置、一次选用动作的稳定标识，以及已有账本时用户明确选择的处理方式。结果必须能核对实际计划、绑定版本及是否仍待完善，不以客户端推测作为创建成功依据。

1. 同一次选用动作重复点击、超时重试或跨标签恢复，只能产生同一结果。稳定标识与账户及原请求内容绑定；同标识换内容须拒绝。结果未知时沿用既有恢复原则，不能换新标识再创建。
2. 对允许多实例的模板，同版本可以被用户明确再次选用；“再次创建一个计划”和网络重试是不同动作，不以模板 ID 简单去重。具体数量上限由服务端控制。
3. 账户没有账本时可创建唯一账本。已有或已归档账本时，不创建第二本；先展示现有账本及拟套用变化，再由用户选择进入现有账本，或显式确认套用新模板的兼容配置。恢复归档、修改目标及调整展示均需明确表达，不能在选用时偷偷执行。
4. 套用账本模板必须保留原账本 ID、记录及退款关系，不将模板默认值覆盖到历史目标；并发选用仍由服务端唯一性及事务保证。多账本和跨币种不在本版范围。
5. 选用成功即创建可在计划列表找到的私人实例，缺必要设置时标记“待完善”；配置草稿依附此实例。初始化取消或校验失败保留原配置及待完善状态，不重复建计划、不产生完成记录；用户可稍后继续或归档该计划；归档保留配置和记录，本版不提供单独彻底删除计划的入口。待完善或已归档账本仍占唯一账本，须恢复原账本继续设置；删除账户按完整数据清理流程处理。可选目标未填不阻塞已有能力。
6. 正式使用试用过的模板时，只复制用户确认的配置。试用记录不默认搬入正式计划；S1–S3 不承诺试用事实批量转正，防止把示例或反复试验算入真实统计。

## 6. 对话、事实与授权

- 创作对话的目标是编辑模板草稿；使用对话的目标是填写配置、记录事实或查询。上下文必须明确当前模式、计划和目标版本；创作过程中提到的示例支出或饮水量不能写入用户账本或正式计划。
- 对话收集用户信息只收集该模板需要的配置。必填信息缺失时澄清；可选信息允许跳过；不能从模板示例、模型猜测或其他人的数据补齐个人答案。
- “我准备每天读 30 分钟”不能被当作已读 30 分钟。“今天读了 30 分钟”也不能在创作预览中自动变成事实；只有正式使用场景下明确的用户事实输入，经过既有校验后才能写入。
- 用户选用模板表示采用其定义，不表示授权模板作者查看数据、启用 AI、发送外部请求或代表用户执行任意动作。AI 授权沿用独立的服务告知和授权版本；未授权时保留手动初始化、记录与管理入口。
- 模板能力、用户操作意图、账户权限、客户端协议能力必须同时满足。模型输出只是一项待校验建议，不能提升其中任何一项。

## 7. 私密数据与公开作品

- 私人创作默认私有。S3 上架是单独、明确的发布动作；发布前展示即将公开的定义、介绍和示例，不能把“保存草稿”或“正式使用”视为同意公开。
- 公开载荷只允许可复用的定义及合成示例，不含个人计划 ID、真实记录、初始化答案、使用对话、创作对话、邮箱或其他凭据。公开标题、描述、默认值也须检查，不能只检查记录表。
- 作者只能管理作品及发布状态，不能因某人选用了作品而读取其私人计划或答案。S3 不默认增加作者查看个人使用统计的能力。
- 模板内容、作者介绍、导入字段文案和用户记录都按不可信输入处理；其中“忽略规则”“导出全部数据”“调用某网址”等文字不能成为系统指令或能力授权。服务端始终从认证会话确定账户和允许访问的资源。
- 前后端都按结构化白名单处理模板，拒绝未知能力及非法字段；文本安全渲染，长度及资源使用受限。不能把作者提供的提示词原样放到高权限系统指令中。
- 下架停止新的市场选用，不删除已选用者的数据。作者注销时撤下市场作品并清理其私人草稿及个人资料；使用者保留不含作者个人资料、足够解释私人计划的定义快照。账户删除后展示匿名作者来源，具体技术保留范围在迁移与清理契约中落实。

## 8. 版本与升级

- 发布新版本产生新版本身份；草稿可反复编辑，已发布版本不可覆盖。市场展示的推荐版本可变，已存在的私人计划仍固定原版本和配置。
- 升级必须由用户主动选择，并预览字段、显示和配置差异；完成后能够说明实际采用的版本。不得因作者发布新版而自动改写私人配置。
- MVP 升级范围仅限：增加可选字段、字段标题或说明调整、兼容的组件排列和展示变化。新增可选字段对历史记录保持缺失，不补造事实；不覆盖已有用户配置。
- 必填字段新增、字段删除或改类型、单位/聚合语义变化、引擎切换、记录拆分合并、账本行为变化均视为破坏性变更，延期到另行设计迁移工具之后。首版拒绝这类原地升级，不以默认值或强制重新初始化绕过限制。
- 升级也要幂等、校验当前版本并处理并发修改。只有数据兼容时才允许回到旧展示版本；如果新字段已经产生记录，旧版本不能解释它们时，不提供会隐藏或丢弃这些事实的回退。

## 9. 旧数据适配、迁移与回滚

现有账本、学习计划、记录及操作历史是保留对象。拟通过兼容适配让旧计划对应明确的内置定义，保留原计划 ID、记录 ID、目标区段、退款关系、输入时间、版本和幂等历史；不要求用户复制记录或重新建账。

实施前需形成并验证以下迁移契约：

1. **先读兼容，再开放写入**：识别旧数据、缺失模板关联和新数据的方式要确定；迁移期间读取结果一致，不因后台适配重算事实。
2. **可重入与可核对**：迁移步骤重复执行不生成重复计划或关联；记录迁移版本与完成状态，核对账户数、计划/记录数量、关键金额和学习汇总，以及孤立关联。
3. **渐进开放**：以能力开关逐阶段开放 generic 和模板写入。旧 ledger/study 操作继续按原业务规则执行，模板关联不能成为绕过规则的路径。
4. **回滚分类**：没有新数据时可按验证方案退回；已经写入 generic 记录或新版本字段后，不能直接退回只认识 ledger/study 的服务。先关闭新增入口，保留能读取新数据的兼容服务；修复后前进，或执行经过核对的恢复方案。
5. **保护真实写入**：备份恢复必须说明恢复点及之后的写入如何保留、核对或恢复，不能把“还原旧备份”当作无损回滚。旧表、字段和解释元数据在完成迁移及恢复验收前不删除。
6. **覆盖全部数据出口**：查询、导出、账户删除、聊天结果恢复和审计/撤销所需材料都包含新实体；不能只迁移计划页面看到的数据。

## 10. iOS 与旧协议兼容

既有 iOS Bearer 认证及 ledger/study 协议继续保留。兼容不仅是登录成功，还包括旧客户端能解码的计划、记录、卡片及历史消息。

- 实施前明确客户端协议能力的协商方式、旧客户端缺省能力，以及新增类型采用独立协议版本还是兼容投影；本文不假定现有接口已有此能力。
- 未完成上述契约及兼容测试前，不向旧客户端开放 generic 或模板新能力写入。尤其是全局聊天，必须在模型能力选择和服务端执行之前限制动作，不能先保存饮水事实再返回旧客户端不认识的卡片。
- 旧协议不返回未经验证的未知枚举、必需字段或卡片形状；需要覆盖同一账户已由 Web 创建 generic 计划后的列表、聊天历史、全局查询、恢复和导出。不能把 generic 数据伪装成 study 来满足旧解码器。
- 兼容读取不得谎称数据丢失或写入失败；如旧客户端不能展示完整数据，须采用经过确认的兼容提示/入口，且不触发重发。该机制没有验证前，相应跨端组合不能发布。
- ledger/study 的真实金额、日期、退款、目标区段和并发规则不能为了模板化而改变。以已支持的 iOS 版本及固定前后端提交组合保存回归证据。

## 11. 分阶段契约完成条件

以下均待实施、待验收；后续任务再固定准确类型、错误契约和测试证据。

| 阶段 | 必须冻结并验证的边界 |
