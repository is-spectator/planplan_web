# v0.4 模板平台验收与阶段放行

状态：已有实施与分项验收，阶段门槛尚未全部完成。逐项现状见 [T01–T45 证据核对](remaining-evidence-map-2026-11-16.md)，本文件保留验收要求，不能把本机通过、生产专项和真人试用混为一项完成。

本文件扩展[共同验收与发布清单](../acceptance-and-release.md)，不替代其中的认证、数据可靠性、真实资源、浏览器、备份恢复和发布要求。既有 36 项浏览器测试属于[旧功能的本机验证记录](../implementation.md)，只能作为回归基线；必须在新的前后端候选组合上重跑，并新增本文场景，不能直接记为 v0.4 通过。

## 1. 执行与证据规则

- 下表每项初始状态均为“待执行”。执行时分别登记通过、失败、跳过或未执行；跳过不计入通过。测试前冻结本阶段字段、单位、统计、模板版本及权限契约。
- 每项证据记录前后端提交、数据库迁移、模板定义及版本、环境、浏览器/设备、输入、期望、实际结果和报告位置。业务写入检查页面、服务端事实与导出，不只判断出现了成功提示。
- 使用隔离账户和带标记的合成数据。清理仅作用于本次生成的数据，不重置真实用户账本或借修改断言消除失败。记录、模板、实例各自的数量与 ID 应可核对。
- 表中金额、目标和字段值为验收样例，不表示产品默认值。S1 阅读沿用 study 的分钟统计；饮水默认单位为 ml，支持明确的 L→ml 换算。饮水标准存储为整数毫升，换算结果也须符合该精度；范围上限等边界在 S1-01 契约冻结后回填具体测试值，不静默改统计口径。
- S1 是官方模板闭环；S2 增加私人对话创作；S3 增加发布和他人选用。后续阶段继承前面已交付能力，修改公共模板引擎后重跑前序受影响场景。

## 2. S1：官方模板与三类计划

| 编号 | 待执行场景 | 可核对的期望 |
| --- | --- | --- |
| T01 | 从官方模板入口分别查看记账、阅读、饮水，选择后初始化计划 | 说明、字段、单位、统计方式与所选版本一致；实例记录来源模板及固定版本；没有把浏览动作当作选用或创建。记账、阅读复用已有领域能力，饮水实际走 `generic`，不是只换标题的学习计划。 |
| T02 | 选用记账模板，预算留空；另用有预算样例验证 20 元支出改为 25 元 | 无预算状态不误显示为 0 元预算；金额分别存为 2000、2500 分，详情、查询及导出一致；更名或展示配置不改变人民币账本的预算、退款和唯一性约束。已有账本时给出复用入口或契约规定的明确结果，不绕过限制另建账本。 |
| T03 | 选用阅读模板，设置每日 20 分钟门槛；同一业务日分别记录两次 10 分钟 | 沿用 study 分钟累计，合计 20 分钟且只计 1 个达标日；修改、删除后按同一规则重算，原有学习目标与周期语义不变。书名、阅读位置可放备注，不将页数当分钟，也不宣称本期提供书库或页数统计。 |
| T04 | 选用饮水模板，以每日 2000 ml 为目标，同日记录 500 ml、300 ml；另验证明确输入 0.5 L | `generic` 的字段定义驱动表单和记录；两条合计 800 ml、进度 40%，每次记录计 1 条；改第二条为 200 ml 后合计 700 ml，删除后为 500 ml。0.5 L 明确换算为 500 ml；“一杯水”未说明数值时澄清，不能猜容量。无记录显示 0，与未设置目标区分，不生成学习时长或账单。 |
| T05 | 填写名称、预算/目标等初始化字段，然后进入记录页 | 创建仅产生计划实例及初始化配置，不凭目标值生成支出、学习或饮水记录；记录表单只出现适用的记录字段。选用成功的实例已在计划列表中；初始化取消或校验失败时保留原配置及“待完善”状态，不产生第二个实例或事实记录；可选目标允许跳过。 |
| T06 | 分别刷新、重新登录、重启 API 后打开三类计划；查历史和记录深链接 | 来源版本、初始化值、记录与统计保持一致；深链接定位正确记录；跨日后新周期与历史分离，无业务写入也能更新当前日期和周期。 |
| T07 | 三类计划归档、查历史、恢复；从模板入口再次选择同一模板 | 归档不删除数据，恢复不复制数据；再次选用遵循明确的复用/多实例规则。允许多实例的模板可通过明确的新建动作创建独立实例，不依靠重复点击产生副本。 |

## 3. S2：私人对话创作

| 编号 | 待执行场景 | 可核对的期望 |
| --- | --- | --- |
| T08 | 用户用自然语言描述一种官方模板之外的记录需求，包含初始化字段、记录字段和统计目标 | 对话形成可编辑的私人模板草稿；缺少必要单位、日期或统计规则时先澄清；没有明确确认前不创建业务实例、不写记录、不发布。用户能看懂最终要收集什么、如何计算。 |
| T09 | 连续修改草稿：新增字段、改名称、改必填/范围，再撤销一次修改 | 最终字段 ID 与含义稳定，删除/改类型的影响可见；只保存用户确认的版本。修改不能遗留界面已隐藏但后端仍要求的字段，或无提示丢弃已有草稿值。 |
| T10 | 用同一自定义模板运行表单、详情、编辑、查询和导出；改变一项字段定义后重新预览 | 支持的字段类型、选项、单位和约束真实驱动界面；服务端重复校验必填、类型、范围和选项。不是静态 JSON 或固定通用文本框冒充自定义表单；未支持的字段/规则在保存前明确拒绝。 |
| T11 | 定义求和、计数、目标进度等本期支持的统计，填入可手算的 2–3 条样例 | 展示值与独立手算及服务端结果一致；新增、编辑、删除都会重算。聚合只引用合法字段，单位兼容；不支持的表达式不能被当作已支持规则保存。 |
| T12 | 在 sandbox 预览中初始化、增改删示例记录、切日期，再退出或重新开始预览 | 能看到真实字段与统计行为；预览前后的正式实例、记录、正式统计和业务恢复队列不变；示例数据不会进入正式导出。保存模板草稿与保存正式业务数据是明确分开的动作。 |
| T13 | 保存私人模板，刷新后重新打开，选用并记录；保存时双击或响应丢失 | 模板定义与版本完整保存；使用确认后的定义创建实例；同一保存请求最多产生一个结果。模板草稿、实例和业务记录各自有可核对状态，不能因模板保存成功就显示“记录已保存”。 |
| T14 | 账户 A 创建私人模板，账户 B 通过列表、搜索、猜测 ID、复制链接尝试访问或选用 | B 不能读取、预览、修改或选用 A 的私人模板；私密字段默认值、创作对话和示例均不泄露。A 的私人模板不会因创建成功自动进入公开目录。 |

## 4. S3：发布、他人选用与版本管理

| 编号 | 待执行场景 | 可核对的期望 |
| --- | --- | --- |
| T15 | A 从私人模板发起发布，查看发布内容后确认 | 发布对象为模板定义和获准展示的信息，不含 A 的计划记录、私人初始化值或创作对话；发布状态、作者和版本可追溯。发布前能发现并清除示例中的私人信息。 |
| T16 | 待审核、通过、驳回、重新提交；普通用户尝试调用审核接口 | 待审核/驳回版本不能被当作已发布版本选用；驳回原因可见，重新提交生成可追溯的候选状态；只有授权审核角色能批准或撤下，越权请求无状态变化。 |
| T17 | B 在模板目录搜索、查看详情、预览后选用 A 的已发布版本 | 目录与详情对可用状态一致；B 看见作者、版本、字段、单位和统计说明，知道选用会创建自己的计划；不可用版本不能通过旧链接或直接请求绕过校验。 |
| T18 | A 发布，B、C 分别选用；三方各记录不同样例，再编辑或删除其中一条 | B、C 各自拥有实例及独立记录；A 不获得 B、C 的明细或修改权限；任何一方的初始化、记录、统计和导出不影响另一方。共享的是模板定义，不是同一计划或账本。 |
| T19 | B 双击选用，在提交成功后丢弃响应并刷新核对；两个标签同时恢复 | 同一选用动作只创建一个实例，使用原稳定 ID 找回同一结果；不会把未知结果当作失败再自动新建。若 B 已有受唯一性限制的账本，冲突结果不会创建另一账本。 |
| T20 | A 或授权审核者下架模板，B 再次打开已有实例，C 使用旧目录页/链接尝试新选用 | 新选用被服务端阻止，目录及时反映状态；B 已有实例按冻结的模板快照继续读取和维护，记录不被删改。下架原因和后续可用范围与实际一致，不能靠隐藏按钮代替权限校验。 |
| T21 | A 发布增加可选字段或调整展示的新版；B 保持旧版，再确认升级；另尝试删字段、改类型等不兼容变化 | 发布新版不静默改变 B 的字段、历史记录或统计。B 能知道当前与目标版本及影响；首版仅放行兼容的新增可选字段/展示调整，确认升级后实际生效，历史缺失值不被自动补成事实。失败可恢复且不混用两版；删字段、改类型/单位等不兼容升级明确拒绝并后移，不以重建实例或丢数据冒充迁移。 |
| T22 | 作者撤回草稿、删除私人模板或删除账户；使用者归档自己的计划或删除账户 | 草稿与私人模板访问随权限终止；作者删除账户时撤下市场作品、清理其私人草稿及个人资料；其他使用者保留解释记录所需的非个人定义快照，显示匿名作者来源。使用者归档计划时保留历史记录与配置；本版不提供单独彻底删除计划的入口。不会误删其他使用者已持有的实例与记录，也不会继续暴露已要求清理的私人信息；账户后台清理状态真实可查。 |

## 5. 每阶段共享的可靠性与防错检查

下列检查从能力首次出现的阶段开始执行，后续阶段均回归。模板发布/升级等尚未进入该阶段的路径可以注明“本阶段未引入”，不能将其登记为通过。

| 编号 | 待执行场景 | 可核对的期望 |
| --- | --- | --- |
| T23 | 金额、小数、空值、0、负数、极大值、非有限数、单位混用；绕过前端直接提交 | 金额始终为安全整数分；generic 数值有明确精度、范围及存储约定，前后端一致。饮水记录要求正数，按 S1-01 冻结的最小步进、上限及相邻越界值测试。空值与 0 区分，非法值拒绝且无部分写入；仅按明示规则转换，0.5 L 转为 500 ml，未说明杯容量时澄清。 |
| T24 | Asia/Shanghai 跨日/周/月、浏览器设其他时区、昨天/未来/无效日期、重试跨午夜 | 业务日期采用服务端日期与已确认的日期解释规则；重试保留原始输入时间和日期，不因午夜改到下一天。无效或不允许的日期拒绝；未来日期按契约处理。查询周期变化不依赖发生写入。 |
| T25 | 初始化时填写目标、起始状态或默认值；记录留空、补全、修改初始化配置 | 目标/预算不进入实际完成量；有“初始累计值”的模板必须单独定义是否计入、从何日起计和如何纠错。默认值不能隐式提交成记录，修改初始化值不能追溯篡改已确认历史；规则不明确时不能放行。 |
| T26 | 模板保存、选用、记录、发布或升级时连点，重复发送同 ID/同体与同 ID/异体 | 每种写动作都有服务端幂等边界；同 ID/同体返回同一结果，同 ID/异体拒绝。真实重复记录走明确确认流程；需要新实例时是用户清楚发起的另一个动作，不以换 ID 自动消除不确定状态。 |
| T27 | 服务端事务已提交但响应丢失，随后刷新、断网恢复、重新登录核对；包含跨计划批次 | 使用原 ID 恢复同一模板/实例/记录结果；数据库只增加一次，回执定位正确对象。成功前不清空必要草稿，不仅靠客户端禁用按钮防重；成功后清理相应恢复材料。 |
| T28 | 结果核对返回 404、处理中、暂时错误或协议解码失败 | 状态保持待核对，按契约退避；404 不等于从未执行。没有自动更换 ID 重发；可重试时保留原请求体和时间。恢复材料缺失时引导核对历史，不能承诺未写入。 |
| T29 | 同一模板草稿、记录或可编辑实例配置被两端先后修改，再用旧版本编辑/删除 | 携带契约规定的 `expectedVersion`；旧版本被拒绝且无覆盖。保留用户草稿，展示最新状态供重新核对；取消、重开或明确重做后才能提交新版本。升级期间的记录编辑也不能遗漏冲突。 |
| T30 | A 有待核对操作时，另一标签将同源 Cookie 切换为 B；A 旧读写和迟到响应继续到达 | 预期账户与实际认证不符时服务端拒绝，B 不产生 A 的实例或记录；旧响应不显示到 B 页面。草稿、查询缓存、恢复队列、创作对话、预览和导出均按账户隔离。 |
| T31 | 两标签同时恢复、两设备同时修改/选用；跨计划批次提交与撤销；恢复期间退出所有设备或删除账户 | 单项协调消费，服务端幂等和版本校验兜底。跨计划批次任一项待澄清时均不写入，确认完整后整批提交或整批失败；撤销仅逆转本批次，保留后续独立记录，任一项存在依赖或版本冲突则整批拒绝撤销。退出/删除明确处理未核对事项，旧会话和迟到请求不能复活已撤销会话或写入已删除账户。 |
| T32 | 拒绝 AI 授权、模型不可用或解析失败，完成官方选用、初始化、记录、纠错、查询 | 手动主流程可完成；S2 支持的字段和规则也有可用的手动编辑/确认路径。模型失败不能丢弃已有数据、产生未经确认的模板，或诱导重复提交业务操作。 |
| T33 | 用升级前已有账本/学习计划执行支出、退款、学习目标、归档、历史、聊天定位及撤销 | 原有数据无需先转成模板才能继续使用；金额、退款上限与跨月口径、学习周期和目标规则不变。旧客户端只访问其支持能力；新类型不能被错误转换成账本/学习或造成旧列表崩溃。 |
| T34 | 下载并实际解压导出；删除测试账户并查询清理状态 | 文件可读且包含应导出的私人模板/来源版本、实例配置、generic 记录和原有数据，字段值与单位足以解释事实；不混入别人数据或预览数据。删除范围覆盖新增数据与本机恢复材料，公共模板及其他使用者实例按 T22 规则处理，不提前宣称全部清理完成。 |
| T35 | 多页模板/计划/记录，切筛选和日期、返回页面、刷新与再次登录 | 无重复、漏项或跨计划遗留分页；空状态、加载、失败、重试可区分。切换计划不会保留上一个计划的新增/编辑上下文；详情、统计和聊天查询最终一致。 |
| T36 | 检查新增 API、缓存、权限、构建产物与日志 | 沿用 Cookie/CSRF/Origin/预期账户保护，未授权请求无写入；私人内容不被公共缓存。日志、前端包和导出不泄露密钥或其他账户数据；模板正文不能决定服务端权限或外发地址。 |
| T37 | 使用旧数据跑迁移、重启并重新读写；在隔离目标备份恢复 | 新旧计划与模板版本可恢复，引用不悬空；迁移不会把已有学习/账本重新初始化。登记恢复及回滚的兼容边界；生产 PostgreSQL 验证继承共同发布门槛，PGlite 通过不替代它。 |
| T38 | 接收未知模板版本、未知字段类型、不可识别统计规则或响应卡片 | 明确提示兼容限制并保留已知事实，不能默默删字段、显示错误合计，或将已成功写入当失败重放。不能安全编辑时阻止该动作，并给出查看/升级客户端等可行路径。 |
| T39 | 模板名称、说明、选项或示例含 HTML/脚本、越权指令、任意公式/外部请求要求；在 sandbox 执行预览 | 作为数据处理，不能执行任意代码、任意 SQL 或越权请求；模板和示例不能改变模型/工具权限。预览与正式业务隔离，退出后不留下可自动提交的正式业务操作；不支持的规则明确拒绝。 |

## 6. AI 解析与创作评测

S1 验证模板实例的记录/查询解析；S2 增加创建与修改模板；S3 增加发布前检查和他人模板上下文。模型不能直接越过模板校验、权限、用户确认或幂等层。

| 编号 | 待执行场景 | 可核对的期望 |
| --- | --- | --- |

## 9. 真实试用提议：3 位创作者、5 位使用者

**T45（待执行，规模提议）**：在对外候选已通过共同发布门槛后，邀请至少 3 位创作者、5 位使用者做独立任务。人数是角色覆盖提议，不是已招募或已通过；若角色重叠，分别登记角色人数和独立总人数，并确保存在不同账户的 A→B 使用关系。沿用现有累计最多 20 个受邀邮箱的范围，不因模板发布自动开放注册。

- 创作者：各自从需求出发完成一种私人模板，修改至少一个字段/规则，预览、确认，并经历发布审核；验证作品不携带私人记录。至少覆盖一种需要澄清单位或初始化含义的需求。
- 使用者：自行发现并选用他人的模板，完成初始化、两次记录、一次纠错、刷新/重新登录后的查询；至少分两次使用，观察日期和历史。共同覆盖官方记账/阅读/饮水及自定义模板，并核对一次下架或新版通知的理解。
- 验收者：记录每项任务是否独立完成、所需提示、耗时、失败原因、数据核对结果及匿名反馈。不能由开发者代操作后记为用户成功；错账、重复数据、泄露或丢数据立即按共同问题分级停止扩大邀请。
- 完成标准：关键数据错误为零；所有核心任务均有独立完成证据。出现阻断或严重问题时修复并重测受影响任务；普通问题登记责任人、限制和后续版本。人数达标本身不表示版本通过。

实际执行后按共同文档的发布记录模板保存版本与证据，并附本文 T01–T45 的结果。现在不创建空的“已完成”发布记录。
