# 验收与发布清单

状态：公网候选已安装，按实际证据逐项验收；完整门禁尚未通过。当前版本与证据见[候选发布记录](releases/2026-11-16-web-beta.md)。本机技术矩阵和部分公网部署/账户流程已执行，v0.4仍须满足[模板平台新增验收](template-platform/acceptance.md)中的真实AI、真机和独立试用要求。

本机开发和阶段验收可以先进行；对外开放才要求本文件的完整发布门槛。当前任务与版本安排见[计划总览](README.md)。

## 1. 每次开放候选体验前都必须通过

- [x] 外网 HTTPS 地址可以打开；深层页面刷新正确；证书、静态资源和 API 路由有效。证据：[源站/公网各135项及续期验证](template-platform/platform-deployment-2026-11-16.md)。
- [x] `/readyz` 验证数据库、迁移和正确后端版本；不能只用进程存活或 `/healthz` 宣告可用。公网返回最终source release，迁移1–17与正式权限验证通过。
- [ ] 真实受邀邮箱完成收信、注册、登录和重置；非白名单不能注册，开发免密入口不可用。真实收件、注册、首次登录、重置后新密码登录及旧会话失效已验证；非白名单拒绝及其余适用生产账户保护需按具体证据收尾，组合项暂不整项勾选。
- [ ] 浏览器 Cookie 登录可用，CSRF/来源校验生效，iOS Bearer 路径不回归；构建产物不含秘密。
- [ ] 真实模型可完成典型记录、查询和澄清；没有授权时不发送用户内容给模型，手动流程可用。
- [ ] 账户 A/B 的页面、导出、记录、历史和本机恢复材料隔离；迟到响应不能串号。
- [ ] 同源多标签切换 Cookie 账户后，旧队列的预期账户校验阻止发错账户；服务端拒绝不匹配请求且不执行写入。
- [ ] 重复点击、请求超时和原结果核对只对应一笔业务写入；404 不是换新操作 ID 重试的依据。
- [ ] 编辑/删除携带 `expectedVersion`；冲突不会静默覆盖；疑似重复及撤销冲突有正确提示。
- [ ] 重启 API、刷新浏览器、重新登录后，已确认保存的数据仍存在。
- [ ] 导出可下载并读取；删除账户有二次确认和准确的后台清理状态；退出所有设备行为符合文案。
- [ ] 账户与业务响应不被公共缓存；只保留已告知的最小恢复材料，并验证清理逻辑。
- [ ] 在隔离恢复目标完成备份恢复核验；在对应测试目标完成受控发布/回滚演练，不覆盖线上数据。正式50表首发空库加密恢复已通过，兼容回滚仍待实测。
- [ ] 当前版本没有未解决的阻断问题；反馈渠道实际可用。

## 3. 浏览器与验证层次

- v0.1 起：自动化覆盖 Chromium、WebKit 的核心流程；人工检查桌面 Chrome、手机 Safari 的真实表现。
- v0.2 起：增加学习、退款、历史、目标和图表在宽屏/窄屏的检查。
- v0.3：补齐桌面 Safari、Android Chrome、真实 iPhone Safari，以及同账户 iOS 联调。浏览器与系统版本写入记录。
- 前端检查包含类型检查、生产构建、协议/状态单元测试及关键端到端测试；不能只有快照或静态页面检查。
- 后端有变更时运行相关认证、业务、恢复测试，以及现有 PGlite/PostgreSQL CI 检查。接口兼容性需要覆盖 iOS Bearer。
- 自动化优先使用合成账户和受控模型；真实环境额外验证真实邮件和少量真实模型流程。付费模型评测不能用模拟响应冒充。
- 若修改模型、提示词或解析规则，按原仓库要求追加完整 AI 评测；普通 Web 展示改动不自动扩展为模型改造。
- 记录通过、失败、跳过与未执行，不以零测试或“预计通过”作为证据。文档自带的历史测试结果不替代本次候选验证。

## 4. 问题等级与停止条件

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| 阻断 | 错账、重复落账、跨账户数据泄露、已保存数据丢失、广泛无法登录、无法恢复 | 停止扩大邀请；定位并修复；必要时按已验证方案回滚 |
| 严重 | 核心操作无可接受替代路径、退款或目标口径错误、移动端主流程无法完成 | 本版不放行，修复后回归 |
| 普通 | 不影响数据正确性的布局、文案或低频交互问题 | 记录影响、责任人和计划版本，向用户披露相关限制 |

不通过关闭校验、跳过断言或重置真实用户数据来使验收通过。

## 5. 发布步骤

1. 冻结候选前端与后端提交，或在未提交工作区以逐文件source manifest固定版本；检查数据库迁移和兼容范围，登记构建产物版本，不虚构Git提交。
2. 在隔离环境运行本版测试矩阵，补齐真实邮件/模型/浏览器证据。
3. 确认备份、恢复、反馈负责人及已验证的回滚路径；迁移变更不能假定可任意退回旧镜像。
4. 先部署必要的兼容后端，再发布前端；探针与匿名检查通过后，用专用测试账户走完整流程。
5. 更新候选版本说明和已知限制，再向本阶段限定用户开放。不要在仓库发布完整邮箱名单。
6. 收集本版要求的试用证据，满足放行标准后确认版本完成；下一版继续复用这套门槛。

## 6. 每版发布记录模板

实际记录填写真实结果；当前已新增[2026-11-16网页内测候选](releases/2026-11-16-web-beta.md)，记录已安装版本与尚未通过门禁，不将候选归档视为全部放行。

- 版本、日期、责任人、状态（候选/已发布/回滚）。
- 前端提交/构建标识、后端提交/镜像标识、数据库迁移版本。
- 体验入口、目标环境、累计邀请规模，不写凭据或真实邀请名单。
- 已运行测试及通过/失败/跳过/未执行数量；浏览器、设备及日志/报告位置。
- 邮件、模型、持久化、恢复、回滚验证结果与证据。
- 真实试用人数、任务完成情况、匿名问题列表。
- 已知限制、阻断项、处理人，以及是否允许扩大邀请。
