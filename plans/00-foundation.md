# 所有版本共用的约定

状态：现行跨版本约定。网页工程、Web会话及部分业务可靠性已在本机实现，证据见[实施进度](implementation.md)；尚未通过对外发布验收。新增模板范围见[v0.4](v0.4-template-platform.md)，各版本继续遵守本文件和[发布清单](acceptance-and-release.md)。

## 1. 产品与架构

- 前端已使用 React、TypeScript、Vite；React Router 管理路由，TanStack Query 管理服务端数据与刷新。依赖通过锁文件固定。
- `planplan_web` 只实现浏览器界面和客户端交互；`planplan/server` 保持唯一业务后端，不复制 AI、账本、目标计算或数据库实现。
- 电脑采用侧栏与主内容布局，按需展开计划详情或编辑面板；基础版本手机采用对话、计划、我的三个入口；v0.4增加市场，创作入口按新版导航约定安排。米色、账本橙、学习青绿和深色模式延续现有设计令牌。
- 对话、计划详情、账户页面具有可直接访问的路由；刷新和浏览器返回保持合理状态。
- 同源部署静态前端与 API：保留 `/v1/*`、`/legal/*` 和探针路由，其余应用路由返回前端入口。静态资源可缓存，账户和业务响应禁止共享缓存。
- 本地开发可用 PGlite；受邀用户环境使用持久 PostgreSQL。MVP 沿用单 API 实例；横向扩容前另行解决跨实例聊天任务协调。

## 2. 现有接口与依赖

| 能力 | 已有接口 | Web 端职责 |
| --- | --- | --- |
| Web邮箱账户 | `POST /v1/auth/web/email/code`、`/register`、`/login`、`/reset`；`GET /v1/auth/web/session` | 验证码、注册、登录、重置与Cookie会话恢复；原无`web`前缀邮箱路径保留给iOS |
| 账户与 AI 授权 | `GET /v1/me`、`PUT /v1/me/ai-consent`、`GET /legal/metadata` | 读取账户、业务日期、数据版本和当前授权版本 |
| 计划 | `GET /v1/plans`、`GET /v1/plans/:id/ledger`、`GET /v1/plans/:id/study` | 列表、月份或周详情；创建/修改通过 operations |
| 记录 | `GET /v1/records/:id`、`POST /v1/operations` | 表单、回执、最新版本与重复记录确认 |
| 操作核对和撤销 | `GET /v1/operations/:clientOpId`、`POST /v1/operations/:id/undo` | 未知结果恢复、同标识重试、冲突处理 |
| 对话 | `POST /v1/chat`、`GET /v1/chat/:clientMsgId`、`GET /v1/messages` | 消息、结构化卡片、历史和处理中状态 |
| 数据权利 | `GET /v1/export`、`DELETE /v1/me`、`POST /v1/logout` | 文件下载、删除确认、真实清理状态和退出 |

复用接口不代表可以直接上线；真实配置、浏览器认证及端到端联调仍需完成。前端请求/响应类型应依据固定后端提交建立，并用契约测试验证，不直接导入服务端运行时和秘密配置。

## 3. Web会话与跨仓兼容约定

本机会话适配已在配套 `planplan` 后端实现。以下约束持续生效，提交与发布前仍需按对应候选组合验证：

1. 浏览器使用Web邮箱适配路由和HttpOnly、Secure、SameSite Cookie；只在明确配置的本机回环来源允许开发Cookie。浏览器响应不暴露长期Bearer Token，前端可读的会话元数据与CSRF token仅在内存使用。
2. 保留 iOS 的 Bearer 登录和认证路径。Cookie 模式的写请求校验来源，并采用 CSRF 防护；拒绝身份冲突的凭证组合。
3. 浏览器退出时清除 Cookie。MVP 沿用现有 `token_version` 全账户撤销行为，按钮明确写“退出所有设备”，确认会影响 iOS；单设备会话后移。
4. 账户和业务 API 使用适当的私有、不存储缓存策略；反向代理不缓存账单、对话和鉴权结果。服务端密钥不进入前端包。
5. 认证、密码重置、删除账户和 Cookie 适配都需回归 iOS 既有接口；用前后端提交组合记录兼容性。
6. Web受保护业务请求和退出请求使用 `X-PlanPlan-Expected-User` 绑定预期账户。服务端将其与 Cookie 实际认证的用户比较，不一致即拒绝且不执行操作；该字段只是防误用校验，绝不作为认证来源。具体适用路由、缺失字段处理和错误码由会话契约测试约束。

当前 beta/production 仅允许邮箱认证、禁止开发登录，白名单最多 20 个邮箱。相同服务和相同邮箱账户才能共享 iOS/Web 数据；测试账户与 Apple 账户合并不在 MVP。

## 4. 从首版开始保证数据可靠

- 客户端在首次提交前生成稳定 `clientMsgId` / `clientOpId`，保留原请求体和原始 `inputAt`。同一操作重试不得改 ID 或修改原请求体。
- 超时、连接中断、解码失败进入“结果待核对”，先调用对应查询接口；聊天 `processing` 保持等待，`transient` 按服务端语义处理。
- 操作查询 404 或聊天 `not_found` 不能证明之前的请求永远不会提交；先退避核对，允许重试时继续用原 ID、原请求体。恢复材料丢失时引导核对历史，不能自动制造新操作重发。
- 同一浏览器账户的提交按序处理；重复点击不创建额外操作。多标签页需要协调队列，跨设备的业务正确性依赖服务端事务和版本校验。
- 编辑和删除显式携带读取到的 `expectedVersion`。409 冲突展示最新记录并要求重新核对，不能静默覆盖。
- 保留重复记录确认、澄清取消、撤销冲突的交互。只有真实成功回执才能显示“已保存”。
- 成功后按 `dataVersion` 更新相关查询；账户切换后丢弃旧账户迟到响应。业务日期统一使用 Asia/Shanghai，不取浏览器所在时区推算周期。
- Cookie 在同源标签页间共享：发送前确认当前账户与队列归属一致，且发送受服务端验证的预期账户绑定；另一标签登录 B 后，A 的旧队列不能以 B 身份写入。登录切换与队列消费跨标签协调，读取结果也不得显示给错误账户。
- `dataVersion` 仅代表业务写入变化；消息历史和 `/v1/me` 返回的 `today` 独立核对。纯查询/澄清、跨日/周/月不能因版本没变而一直显示旧内容。
- AI 回复按 receipt、plan、query、clarify、error、notice 等已有结构渲染。当前接口是完整 JSON，无需为 MVP 新增流式协议。

## 5. 小版本能力兼容

v0.1 主推记账，但现有全局 Bot 仍能创建学习计划、退款和调整目标。采用“完整卡片协议 + 简版详情”的策略：

- 首版必须展示所有已有卡片变体和必要字段；任何成功记录都可定位、查看，并有适用的纠错、删除或撤销入口。
- 学习计划即使尚无专门的完整页面，也提供基础周摘要、记录列表和返回对话的入口；已有退款可查看原支出关联。
- v0.2 完善专属表单、图表、历史导航和管理体验，不是第一次承认这些数据存在。
- 不支持的新协议返回明确的兼容提示并保留已知结果，不能把已经保存的操作显示为失败或自动重发。

如果不能保证上述兼容，必须先增加服务端能力限制并验证“未支持操作没有写入”；单纯隐藏前端入口不能作为降级方式。

## 6. 本机数据与离线边界

- MVP 默认不持久缓存完整账单、学习明细或聊天历史，不提供完整离线使用。普通离线输入仅留在当前页面草稿，恢复网络后由用户发送。
- 为支持已提交但结果未知的恢复，可以在按账户隔离的 IndexedDB 中保存最小未完成操作队列：ID、原输入时间、状态和同体重试必需的请求内容。内容可能包含输入文字和金额，需向用户说明本机会保存，不能称为零留痕。
- 成功核对或服务端语义允许的明确取消后清理恢复材料。到期项停止重试并提示核对历史；结果未知时不得静默丢弃材料或重发。
- 清理浏览器数据前提示未核对事项；退出、账户删除和账户切换严格处理当前账户的本机恢复材料，不能跨账户读取或发送。
- 不依赖浏览器关闭后的后台上传，不用 Service Worker 自动重放业务写入。PWA 安装和长期离线队列属于后续版本。

## 7. 对外环境准备

需要落实：HTTPS 域名与证书、静态前端和 API 路由、持久 PostgreSQL、受控迁移、邮箱白名单和真实邮件服务、模型配置、审核后的服务告知、加密备份及恢复位置。

现有部署文件只提供契约，不代表域名、资源、密钥、邮件或模型已经配置。开发可以先本地推进；真实资源缺失时不得发送“已经可以体验”的邀请。

所有秘密通过部署环境的安全配置提供；规划、仓库、前端构建产物和发布记录不存秘密值或完整邀请邮箱名单。外部资源的实际开通和部署另按实施任务执行。

## 8. v0.4模板平台扩展

- 模板、不可变版本、私人计划、个人配置与真实记录分开；选用、初始化和结构升级同样适用账户隔离、幂等和版本校验。
- 官方账本／阅读适配既有引擎，新通用记录能力独立加入；模板文字不授予执行代码、外部请求或跨账户读取权限。
- 已有客户端在能够完整识别新记录类型前，不得触发该类型写入；能力协商与读取兼容在开启generic前完成。
- 新记录需进入导出、删除账户、归档恢复及适用撤销流程，不能只实现写入和展示。
- 创作预览、试填数据和公开示例与真实账户记录隔离。版本升级不自动覆盖已选用的计划。
- 范围与阶段顺序见[v0.4总计划](v0.4-template-platform.md)；具体约束见[模板契约](template-platform/contracts-and-data.md)和[新增验收](template-platform/acceptance.md)。
