## 已核实的问题

基线为单仓 `main` 提交 `7c03257934444a4d2dcdcdc1bb486b19b378488c`；以下为源码观察，实施者仍应先执行受控复现。

1. `src/pages/ReviewPage.tsx` 中举报查询只传 `status`，无 `limit/offset`；页面仅渲染返回的举报数组，没有举报分页按钮。API 默认返回 20 条，所以对应状态的第 21 条及以后举报没有页面入口。
2. 同页送审作品有独立 `offset`，但仅在 `total > 20` 显示分页。处理末页最后一条、导致总数变为 20 或更少时，旧 `offset` 未校正，可停在空页且分页消失。
3. 送审分页显示的是 `${offset + 1} / ${total}`，不是清晰的页码或当前范围；请求中未禁用翻页。列表读取失败只显示文字，缺少各队列自己的重读入口。

后端已经支持所需参数：`server/src/api/platform.ts` 的公共分页 schema 为 `limit` 1–100、`offset` 0–10000 的整数，默认 20／0；`/v1/community/review` 与 `/v1/community/reports` 都使用它。`server/src/services/community.ts` 的两个列表服务已按 `created_at,id` 排序。本 PR 无需新增接口或修改审核状态机。

## 拟实现的用户行为

| 队列 | 保留筛选 | 新行为 |
| --- | --- | --- |
| 送审作品 | 待审核／已通过／已退回 | 显示清楚的当前范围或页码；独立翻页；成功处理后按最新总数恢复有效页。 |
| 举报处理 | 待处理／已处理并暂停展示／无需下架 | 每页 20 条，独立上一页／下一页；能够读取后续页并处理指定举报。 |

两组筛选、页位置、加载与重试互不混用。改变送审状态只重置送审第一页，改变举报状态只重置举报第一页。读请求失败不清空另一组内容，也不把失败显示成“暂无”。

处理一个对象后刷新对应队列；对象从当前筛选移走导致页越界时，回到最后有效页。另一组队列的位置不变。若总数归零显示对应空状态，不能显示倒置范围或把读取失败当成处理完成。

## 实施要求

### 1. 独立请求与分页状态

举报请求增加明确的 `limit=20` 和当前 `offset`，查询键包含本账号、举报状态与 offset。送审和举报分别持有自己的分页状态，不共用单个 offset；请求返回顺序不决定当前页面状态。

本 PR 的页位置可以继续保留在当前页面内存，不要求刷新或外部深链接恢复审核位置。若实施者选择使用 URL，应仅增加本队列受控参数，不引入依赖 PR-003 市场导航的共享框架。

成功响应的 `total` 用于越界校正；加载中／失败时保留可理解状态，不用缺省零触发回第一页。正常页不重复请求；越界校正到有效页后重新读取，避免不断向无效 offset 请求。分页边界不得超过现有服务端最大 offset 10000，禁止扩大 API 上限或声称无限数据规模已经覆盖。

### 2. 处理与恢复保持原语义

审核表单仍要求原有核对勾选，退回／举报处理仍按现有规则填写说明。提交继续使用对象原 `expectedVersion`、原动作和 `useCommunityRequest`；不能因为列表刷新就自动确认、重新生成请求 ID 或重复发出处理动作。

只在确认处理成功或既有恢复链确认成功后刷新列表并判断位置；网络中断、结果未知、版本冲突继续呈现既有反馈。分页与筛选不触发业务 POST，不接受“换一页”作为取消恢复任务。

保留 `ReviewSubmission` 和 `ReviewReport` 的现有作用范围，避免翻页后的组件复用把前一对象的处理说明、勾选或决定带给新对象。已有未提交说明不能被后台轮询或无关队列动作静默覆盖；用户主动离开当前页仍沿用现有表单行为，本 PR 不新增离线草稿系统。

### 3. 可区分的反馈与入口

为两个分页导航提供不同的可访问名称，例如“送审作品分页”和“举报分页”；每个列表有自己的加载、失败、重试与空状态。翻页控件在该队列读取期间适当禁用，另一个队列可继续浏览。

当前范围根据实际返回条数和总数计算；空队列不显示“1–0”。320px／390px 窄屏上可找到全部分页、状态与处理按钮，不用加入后台技术信息或请求 ID。

审核角色控制与服务端权限校验完全保留。测试使用现有隔离合成角色，不创建公网审核账号，不替真人作内容审批结论。

| 场景 | 必须满足 |

| 某状态有 41 条举报 | 20／20／1 三页都可达，第一页不显示可用的上一页，末页不继续请求空下一页；对象 ID 不串页 |

| 一个队列读取失败，另一个正常；重读时旧请求迟到 | 错误只属于对应队列；可重读，旧条件数据不覆盖新条件，失败不显示“暂无” |
| 处理响应丢失、版本冲突、连续点击 | 既有恢复与 expectedVersion 校验保持；不因翻页或刷新重发处理，不错误宣称成功 |

| 非审核角色与 320px／390px 窄屏 | 原权限限制保持；授权合成角色能通过清楚的分页名称与键盘完成浏览 |
