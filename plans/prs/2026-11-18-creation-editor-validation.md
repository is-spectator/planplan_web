## 目标行为

编辑期间保留用户已填的字段、统计名称、目标选择和其他内容。发现引用或口径冲突时，在对应统计处说明“哪个项目、为什么不适用、怎样修正”；保存时阻止无效请求，并把焦点带到可修正的位置。

例如：“每周阅读进度”和“每日阅读进度”不能共用同一个目标设置；用户可以为它们选择不同目标项目，或统一周期与计算方式。界面不应擅自改目标值、周期或删除某个统计来让保存通过。

## 实施范围

### 1. 为手动编辑增加局部关联校验

可新增 `src/features/creation/definition-validation.ts`，接收正在编辑的定义，返回可定位的问题集合。按字段／统计的稳定 ID 定位，不依赖它们在数组中的索引，也不将内部 ID 直接显示给用户。

至少覆盖：

- 求和／均值的来源仍存在，且属于当前支持的数值类型；记录天数引用日期；计数不带数值来源。
- 分类引用仍存在，且是单选或布尔字段；字段改类型后，旧引用必须显示为待修正，不能视觉上显示有效却仍提交旧值。
- 目标进度引用的设置仍存在；求和目标与来源类型、单位一致，次数／天数目标为无单位整数，目标下限符合现有大于零规则。
- 同一 `goalFieldId` 在多个目标进度中，周期、规范化后的聚合方式及来源必须一致；缺省 `goalAggregation` 按现有 `sum` 语义比较。
- 记录来源、分类或目标发生变化后重新校验，修正后错误消失；不把一个错误固化为无法恢复的编辑状态。

局部校验依据现有服务端契约，只补当前网页能编辑的关联关系，不复制整个后端 schema，不引入新的模板能力。不能把服务端模块及其数据库／运行时依赖直接打进前端，也不能为了减少报错而放宽后台校验。

### 2. 错误就近显示并可定位

在相关统计区域展示具体错误；保存时增加简短错误汇总，能通过键盘定位第一个有问题的控件。控件使用适用的 `aria-invalid`／`aria-describedby`，手机长页面也能找到问题。

必填检查、当前已有的字段范围／选项／默认值校验继续有效。处理原生校验与自定义校验的先后，避免浏览器拦住提交后既没有可定位反馈，也无法看到隐藏的失效引用。无需改全站表单组件。

已保存字段的类型和单位继续锁定。本 PR 不新增自动删除统计、自动换目标、自动猜单位或自动清空建议值的行为；原有“移除项目”的明确确认及说明保持，不扩大删除范围。

### 3. 保存与恢复边界

本地关联校验失败时，不发出创作 `update` 请求、不调用模型、不改变服务器草稿版本。修正后通过现有 `onSave` 保存，仍由服务器做完整校验及版本冲突检查。

后台拒绝、版本变化、请求未知等继续沿用现有链路，不在本 PR 中改恢复协议。编辑器外部的 `locked`、`initial`、`today`、`onSave`、`onCancel` 约定保持，使 PR-002 能直接打开同一个编辑器。
