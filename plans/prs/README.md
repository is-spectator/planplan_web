## 给实施者的共同要求

1. 拉取本仓库最新 `origin/main`，检查工作区及已有 PR。每项使用单独的 `codex/` 分支；不要重复搬入已存在的前后端，也不要覆盖他人修改。当前可追溯的单仓代码基线为 `cdc03cf398446ec4dee23f37c50b028994b4f22d`，实施应基于最新主分支。
2. 先读所领取的计划书，列出实际 TODO；每项实现并验证后才勾选。状态从“待实施”改为“实施中”，提交评审时附实际分支、PR 链接和测试结果，合并后再标“已合并”。
3. 复用已有表单、恢复和账号隔离机制。验证使用合成数据与隔离本地环境；这两项不需要真实模型调用、公网账号、邮件或生产数据。
4. PR 描述交代问题、最终行为、验证及未完成项。历史测试通过数不能替代新差异的验证；协议模拟、真实本地 API、真实模型和生产验证分别记录。
5. 本目录是实施交接，不自动创建 GitHub PR、合并或部署。实施者交付可审查 PR；后续部署单独记录实际版本与验收，不能把“已合并”写成“已上线”。
