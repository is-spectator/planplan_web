## PR 定义

- 建议标题：`ci: 验证单仓构建、数据库回归与网页核心流程`
- 建议分支：`codex/web-ci-checks`

## 检查设计

| 检查 | 最小要求 | 失败结果 |
| --- | --- | --- |
| 网页静态检查与构建 | 干净检出，按根锁文件安装，执行 typecheck、lint、build | 任一命令失败则该检查失败 |
| 后端与 PostgreSQL 15 | 按后端锁文件安装，typecheck/build，使用临时 PG15 服务运行后端确定性回归；保留 CI 并发上限 | 测试失败、清理失败或必测用例被跳过均不能算通过 |
| 网页协议回归 | Chromium／WebKit 的受控 HTTP 用例；明确识别混合测试文件中的真实 API 段及跳过原因 | 协议核心用例不能零执行；失败保留首错，不靠自动重跑转绿 |
| 最小真实本地 API 闭环 | 新的自包含 smoke：手动创建／使用计划并保存、刷新核对一条记录；手动编辑并保存私人模板，再采用且确认没有伪造记录 | 启动、登录、页面动作或 API 数据断言失败均使检查失败；不能因缺环境变量静默跳过 |

“真实本地 API”指实际运行本仓库 API 与隔离数据库，模型仍是受控实现，不等于真实模型质量。测试只使用 fixture 合成账号，可沿用已公开的本地测试凭据，不配置 GitHub Secrets、不发真实邮件。

### 环境和生命周期

- 使用 Node.js 24 和仓库指定的 pnpm 10.33.2；网页执行 `npm ci`，后端执行 `pnpm --dir server install --frozen-lockfile`。不为搭建 CI 升级依赖或重写锁文件。
- 安装与项目锁定 Playwright 版本匹配的 Chromium／WebKit 及 Linux 系统依赖，例如在安装项目依赖后执行 `npx playwright install --with-deps chromium webkit`；不能假设 runner 自带可用浏览器。
- 每个 job／浏览器项目使用独立运行环境或严格串行的独立数据集，不能同时占用同一 fixture 数据目录和相同账号状态。本地验证须在临时干净 checkout／容器中运行，不停止用户已有预览服务。
- 专用 CI 配置明确指定网页 URL 和启动命令。新 smoke 不硬编码另一端口，不加载本机 `.env.*`、旧 storageState 或历史证据文件；不要求顺便重构全部旧 live 用例。
- 对 fixture 的就绪检查设置合理超时，失败保留日志；退出与测试失败均关闭本 job 启动的服务、清理临时资源。只清理本 job 明确拥有的目录和进程。
- 显式保持 `PLANPLAN_FIXTURE_REAL_AI` 为关闭状态，避免继承模型或邮件凭据；测试不访问生产域名和数据库。
- PostgreSQL 使用本 job 临时服务与测试 URL；继续让现有夹具负责 schema 隔离。不从部署配置提取测试数据库信息。

### 触发、结果和证据

- 检查面向本仓库 PR 和 `main` 的 push；允许手动触发。取消同一分支较旧的检查，不能跨分支取消其他人的任务。
- 使用满足检出与上传检查产物的最小权限；不使用能让外部 PR 以高权限执行代码的触发方式。这里不需要发布、评论机器人或生产凭据。
- 报告标明 commit、检查组、执行／通过／失败／跳过数量。不能把跳过用例计为通过，也不能把一次 smoke 写成完整历史验收通过。
- 保留有限期限的必要失败截图、trace 和精简日志；只含合成数据。不要上传全部 `.data`、浏览器会话文件、环境变量或开发机历史证据。
- 有意制造一次独立的检查失败，证明流水线会报红；恢复后证明正常路径能通过。保留两次运行记录，不能通过删除断言、增加自动重试或排除失败测试取得绿灯。
- 功能 PR 新增的专项测试应自动被合理收集，或在合并时显式接入对应组；避免固定白名单导致后续 PR 的测试永远不跑。
- G01 应产出按浏览器项目的用例发现与分类清单，核对发现集合与实际执行集合。固定 smoke 场景必须在两个浏览器逐项执行且无 skip，不能只要求总执行数非零。协议组只允许清单中注明原因的既有 live 段跳过；未知 skip、未归类的新用例或遗漏的必测场景应使检查失败。测试总数不写死为历史数字。
