## 已核实的问题

基线为单仓 `main` 提交 `7c03257934444a4d2dcdcdc1bb486b19b378488c`；下列为源码观察，不是已经执行的浏览器复现或本 PR 验收结果。

1. `src/pages/MarketPage.tsx` 的 `text` 只用 `useState(search.get('q') ?? '')` 初始化；列表查询持续读取 URL 的 `q`。同一路由前后退改变 `q` 时，搜索框与实际查询可能不一致。
2. 卡片进入 `/market/:templateId` 时不携带列表上下文；详情“返回市场”固定指向 `/market`，会丢失搜索、来源、分类及页位置。
3. `offset` 直接用 `Number()` 读取，`source`、`category` 也直接取 URL。非法或手工编辑的链接会把无效参数送到 API，显示为读取错误。
4. `templates.length === 0` 一律显示“还没有可用的模板”，不能区分没有搜索匹配、目录为空和当前偏移已过期。
5. 分页只在 `total > 20` 时出现，没有按最新总数校正 `offset`。下架或筛选结果变化后，旧分页链接可能停留在空页，甚至失去上一页入口。

服务端 `server/src/api/platform.ts` 已明确支持：`limit` 为 1–100，`offset` 为 0–10000 的整数，`q` 去空白后最多 80 字，`source` 为 `all|official|community`，分类使用现有枚举。网页现用每页 20 项。本 PR 沿用此契约，不改 API、排序、模板可用性或采用行为。

| 场景 | 目标行为 |
| --- | --- |

| 列表进入详情，再点“返回市场” | 回到原来的有效筛选及分页；详情刷新后仍有可靠返回位置。直接打开详情则返回普通市场首页。 |

| 模板减少导致当前页越界 | 根据本次成功响应的总数校正到有效页，替换失效 URL，不显示倒置范围或永久空页。 |

## 实施要求

### 1. 明确 URL 与输入状态

将已提交的 `q/source/category/offset` 归一化后用于查询键和请求，避免表单显示与请求使用两套条件。正常文字编辑不应触发每键搜索或被无关后台刷新覆盖；提交、重置以及 URL 导航才更新已提交状态。

来源和分类只接受现有白名单；无效来源回 `all`，无效分类清除。网页页位置使用 20 的倍数；非整数、负数、非有限值、超过 10000 或不对齐的 `offset` 统一回第一页，并以 `replace` 修正 URL，避免历史记录堆积。`q` 超过契约长度时提供可修正的输入提示，不发送非法请求，也不静默截断后假装搜索的是完整原文。

只把市场支持的字段传给严格校验的 API。保留现有分类集合和搜索匹配规则，不新增排序、热门推荐、模糊搜索或自动联想。

### 2. 返回位置与过期页

列表到详情传递的返回信息限于市场路径与白名单筛选参数；采用刷新后仍可恢复的方式，具体使用受控查询参数或路由状态由实施者选择并验证。不能信任任意 `returnTo`、外部 URL 或脚本协议。直接详情访问与缺少／无效返回信息时回 `/market`。

返回位置与 `templateId`／API 请求参数分开处理，不改变当前模板详情的读取、登录后返回、试填、举报、创作来源或采用后进入私人计划的行为。

成功读取后才按 `total` 判断越界；失败不能当成总数为零。采用固定页长计算最后有效页，清除过期偏移或替换为有效偏移后再读取一次，防止循环请求。翻页只发读取请求，加载时避免连续翻页产生不清楚的位置；迟到的旧条件响应不能覆盖当前条件。

服务端允许的最大 offset 仍为 10000；客户端不得发出超过约束的下一页请求，也不得把服务端未提供的更大范围宣称为已遍历。本 PR 不扩大服务端分页上限或实现目录快照一致性，海量目录方案另行规划。

### 3. 保留页面可用性

分页范围以本次实际返回数量与总数显示，空目录不显示“1–0”，过期页不短暂展示“41–20”。搜索无匹配可以清除筛选，清除后回第一页；仍有未提交输入时，操作含义应明确。

保持“样式预览＋功能简介”的卡片结构，不做页面重设计。桌面键盘、320px／390px 窄屏能完成搜索、翻页和返回，状态提示可被辅助技术识别。所有这些读取动作均不得创建计划、写记录或调用模型。
