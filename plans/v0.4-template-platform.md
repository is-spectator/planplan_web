## 1. 用户价值与完整流程

用户通过对话设计自己的记录工具，也能直接选用官方或其他用户的模板。选用后得到私人计划，对话负责收集必要设置与每次记录，计划页面展示可核对的真实结果。

创作模板 → 预览与试填 → 保存为私人模板／申请公开 → 市场选用 → 进入个人计划 → 对话设置 → 持续记录、查询和纠错。

新增「创作」「市场」两项产品能力；「对话收集信息填写模板」是所有模板共用的能力。参考 Base44 的自然语言修改、预览、模板选用和独立副本机制，以个人记录与目标管理为首版范围，通过受控字段、规则和组件生成可用工具。

## 2. 已确定的产品决策

| 事项 | 本版约定 |
| --- | --- |
| 模板／计划／记录 | 模板定义结构与规则；计划是某用户选用某版本后的私人实例；记录是实际发生的事实 |
| 入口 | 桌面提供对话、计划、市场、创作、我的；手机主导航为对话、计划、市场、我的，创作从市场与我的作品进入 |
| 创作工作区 | 桌面对话与实时预览并列；手机切换对话／预览；修改可撤回，草稿可续接 |
| 默认可见性 | 作品默认私有；保存、自己使用、提交公开是独立操作 |
| 模板选用 | 点击后立即进入自己的计划；待补充必要设置时在计划列表显示「待完善」 |
| 配置收集 | 仅追问影响使用的必填项；可选目标允许跳过；确认设置不产生完成记录 |
| 日常记录 | 完整明确的事实直接保存并提供回执；缺失／歧义先澄清；支持表单及修改、删除和适用撤销 |
| 信息复用 | 只收集当前模板需要的信息；跨计划复用个人信息需用户明确选择；作者不能读取使用者答案 |
| 示例和试填 | 使用独立试用数据；不进入个人统计，不发布真实记录或创作对话 |
| 市场来源 | 官方与社区模板；作品管理放在创作入口，官方标识由服务端控制 |
| 发布与升级 | 公开版本不可变，计划固定绑定选用版本；更新生成新版本，使用者自主升级 |
| 计划移除 | 本版采用归档／恢复，不提供单独彻底删除计划；待完善计划也可归档，删除账户按完整清理规则执行 |
| 原有账本 | 保留每人一个人民币账本；再次选用记账模板明确引导到已有账本，不自动改预算或覆盖历史 |
| 实例个性化 | 计划设置只作用于该计划；结构修改生成私人派生版本，不修改市场原作；派生作品首版仅供自用 |
| 收费与外部能力 | 本版模板免费；支付分成、任意代码执行、外部连接器和复杂自动化后移 |

已安装模板下架或作者删除账户后，使用者已有计划与数据继续可用；作者作品从市场撤下，私人数据分别遵循各自账户的数据删除流程。

## 3. 首版模板能力

| 能力 | 范围与约束 |
| --- | --- |
| 字段 | 文本、数值、金额、日期、时长、单选、多选、是否完成；稳定字段标识、单位、必填性与校验规则 |
| 配置 | 名称、开始日期、可选目标及用户明确选择的默认值；模板默认值与个人答案分开 |
| 目标 | 按日／周／月累计时长、次数、有效记录天数或数值；预算复用账本专用规则；目标变更按生效周期处理 |
| 统计 | 求和、次数、平均值、按日期或分类汇总、目标进度；仅使用预定义运算与合法字段 |
| 页面 | 摘要卡、记录列表、进度条、简单趋势，允许选择显示内容和顺序 |
| 操作 | 选用、初始化、记录增改删、查询、核对、导出、归档恢复，以及支持的撤销 |

日期遵循上海时区；金额沿用整数分；通用数值定义精度、合法单位和可换算关系。空值与零分开处理，平均值须明确有效记录的分母。页面读取到上海日期变化后保留未提交输入，目标的受影响周期变化须再次核对；这一保护依赖`/me.today`已刷新，15秒轮询及失败退避窗口仍保留。URL分页恢复不等于并发写入下的一致性游标；后台分页三项后续范围见[日期专项](template-platform/business-date-verification-2026-11-17.md)。

本版保留原有 `ledger/study` 业务引擎，通过适配关联官方模板；`generic` 字段、持久化、校验和聚合能力承载饮水及私人/社区模板。当前范围以[通用扩展与社区平台契约](template-platform/platform-contract-v2.md)为准，并保留[记账与通用记录v1契约](template-platform/ledger-generic-contract-v1.md)的兼容约束。S1阅读沿用时长统计，书名和阅读位置可通过明确备注兼容；S2以generic新建私人阅读模板验证结构化字段，已有study计划跨引擎迁移后移；不将“读到第35页”当成本次阅读35页。

S1饮水采用整数毫升数值与明确单位：默认ml，支持L到ml的明确换算；同日500ml加300ml汇总800ml，目标2000ml时进度40%。没有容量的“一杯水”需追问，不猜固定值。范围上限和目标生效规则在S1-01冻结。

详细定义、数据迁移与版本约束见[模板契约与数据](template-platform/contracts-and-data.md)。

## 5. 对话与页面约定

创作对话和记录对话拥有独立历史、上下文与草稿。创作界面显示正在设计的模板；记录界面显示选中的计划。日常记录不会悄悄修改模板结构。

全局对话按用户明确指定的计划或当前计划范围处理，范围冲突或多个候选时询问。默认沿用内容须由用户设置且体现在回执中；完整事实可直接保存，模糊事实不能凭空补齐。

归档计划仍可进入计划内对话查历史；新增记录先确认恢复，不能因当前计划已归档或明确ID无效而写到另一个活跃计划。退款唯一明确匹配才关联原支出，其余提供候选；未到账/未来或外币退款不误写人民币事实。删除原支出须核对固定关联退款快照，变化后重新确认，成功回执优先恢复。跨含义修改模板字段先澄清，不得删旧字段后另建替代绕过确认；未知杯容量等计量含义也应追问，不能借新增字段假装需求已满足。完整质量门槛仍按当前独立评测与人工审定判断。

分类支出查询回答须尊重分类，不能展示全月预算作为该分类结果；明确查询预算仍使用整月口径。聊天批量清空、多条或含删除的混合批次应整体停止，不能把模型看到的最近记录当作“全部”；F08已补齐跨标点表达保护并通过新增专项，真实模型效果另按完整独立评测核对。

跨计划的一句话先整理所有写入项，未确定时集中澄清；完整后通过统一操作原子提交并逐项显示回执。S1即验证官方类型的多计划批次；没有原子保存能力前引导按计划分别记录，不允许静默部分保存。

详细示例、默认规则、缺失处理和设计／填写切换见[对话与用户流程](template-platform/conversation-and-flows.md)。用户页面保持产品语言，不展示schema、调试JSON、构建版本或开发状态；必要状态如待完善、待审核、保存中正常显示。
