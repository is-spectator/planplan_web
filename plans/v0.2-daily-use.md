# v0.2：日常账本与学习管理

状态：待实施。依赖 [v0.1](v0.1-first-use.md) 已发布且无遗留阻断问题。建议累计邀请 5–10 人。

## 用户价值

用户可以每天记录消费和学习，回看历史，调整目标并修正数据。两类计划都有完整的浏览器操作入口，不必为常见操作反复描述给 AI。

## 范围

| 能力 | 相对 v0.1 的增量 |
| --- | --- |
| 学习计划 | 完善已有基础创建入口，增加多计划管理、专属时长表单、周目标、7 日状态、历史周切换 |
| 目标管理 | 月预算、每日分钟数及每周天数；本期、以后和下期生效范围按后端规则展示 |
| 账本详情 | 历史月、分类支出/退款/净额、每日趋势、记录分页 |
| 退款 | 从原支出发起部分或全额退款，显示关联与剩余可退款额 |
| 计划管理 | 重命名、归档、恢复、进行中/归档筛选 |
| 记录管理 | 完整手动表单、源消息定位、删除含退款记录的确认、撤销冲突处理 |
| 体验状态 | 无预算、目标不完整、未记录、已记录未达标、已达标、归档及空周期 |

小屋、同行榜和周卡继续后移；不增加收入、多币种、独立旅行账本或任意待办类型。

## 实施工作包

- [ ] 学习详情、时长表单与周导航，完善 v0.1 基础兼容页。
- [ ] 预算和学习目标表单；展示生效范围、首周调整及规则变更回执。
- [ ] 账本历史月份、分类汇总和可表达负净额的趋势图。
- [ ] 退款及关联删除确认；超额退款失败时保留原数据和用户输入。
- [ ] 计划重命名、归档和恢复；归档不误表示删除，唯一账本可恢复。
- [ ] 记录编辑、来源、分页和空状态；任何图表数字来自服务端。
- [ ] 扩展浏览器端到端测试，补目标、退款、历史与页面/聊天一致性用例。

预计主要复用现有接口。若发现字段缺失，应在 `planplan` 增补明确契约及测试；不得用前端自行计算替代服务端规则，也不复制一套后端。

## 验收演示

1. 创建“阅读”和“英语”两个计划；选择计划记录时长，确认记录只归属一个计划。
2. 选择完整测试周，设置每周 5 天、每天 20 分钟。某天两次各记 10 分钟，显示总计 20 分钟且只有 1 个达标日。
3. 在目标不完整的计划记录 30 分钟，只显示记录情况；未记录、未达标和已达标三个状态可区分。
4. 调整下周目标，检查本周统计不被下周规则改写；另测首周中途开始时的目标口径。
5. 在独立账本数据中新增支出 100 元，再关联退款 30 元，同月净额为 70 元；超额退款被拒绝。
6. 增加一笔跨月退款，核对按退款发生月份统计；查询卡、详情和导出结果一致。
7. 归档再恢复一个学习计划，历史不丢失；归档账本后恢复原账本，不创建第二个账本。
8. 连续 3 天完成记录、查看与纠错。此处是真实试用要求，日期模拟测试不能代替完成记录。

## 候选开放与版本完成

先通过以下技术条件，再向本阶段 5–10 人开放候选版：

- [ ] v0.1 全部共用门槛继续通过，新增流程无阻断问题。
- [ ] 两类详情的数字、历史范围及目标口径通过合成数据核对。
- [ ] 退款关系、删除确认、重复记录确认和版本冲突通过测试。
- [ ] 发布记录包含已知限制、数据兼容性、前后端提交和回滚结果。

候选开放后，至少 3 位受邀用户完成连续 3 天试用并留下结构化反馈；阻断问题解决后才确认 v0.2 完成。
